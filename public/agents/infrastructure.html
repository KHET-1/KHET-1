Infrastructure Modifications for Best PCAP Results

1. Network-Level Capture (Best Shape)

For highest fidelity, capture at the router/gateway level — sees ALL device traffic without per-device agents.

MethodSetupCoverageEffort
Router mirror port (SPAN)Enable port mirroring on your switch/router to a monitoring NICAll LAN devicesLow
Transparent bridgeLinux box with 2 NICs inline between router and LANAll traffic through bridgeMedium
DNS sinkhole (Pi-hole)Force all DNS through Pi-hole, log all queriesDNS only (but reveals all destinations)Low
WiFi monitor modeSeparate adapter in monitor mode on same channelAll WiFi (may be encrypted)Low
Recommendation: If your router supports it, enable a SPAN/mirror port sending all traffic to your Parrot box (192.168.2.46). Then run tcpdump on that mirrored interface. This captures phone drip without needing anything installed on phones.
# On Parrot box with mirrored port on eth1:
sudo tcpdump -i eth1 -w /tmp/all_devices.pcap -c 50000

# Or filter to just phone IPs:
sudo tcpdump -i eth1 host 192.168.2.XX -w /tmp/phone_traffic.pcap

2. ARP-Based Passive Capture (No Router Access Needed)

Use ARP spoofing to position your Parrot box as man-in-the-middle. See all phone traffic without touching the phone.

# On Parrot box — become the "router" for target phone:
sudo arpspoof -i wlan0 -t PHONE_IP GATEWAY_IP &
sudo arpspoof -i wlan0 -t GATEWAY_IP PHONE_IP &
sudo sysctl net.ipv4.ip_forward=1

# Capture everything flowing through:
sudo tcpdump -i wlan0 host PHONE_IP -w /tmp/phone_mitm.pcap
Android vs iOS: No difference — this is network-level, device-agnostic.

3. DNS-Level Monitoring (Lightest Touch)

If you control the DNS server (or DHCP), every device reveals its destinations without full packet capture.

# Pi-hole or dnsmasq with full query logging:
sudo pihole -t   # tail live queries

# Or run a DNS proxy on your Parrot box:
sudo tcpdump -i any port 53 -w /tmp/dns_all_devices.pcap

Triangulation — Getting Best Shape

Triangulation Method: 3-Point Correlation

Run capture simultaneously from 3 vantage points to triangulate the drip:

PointWhat it seesTool
A: Source device (phone)Process → connection mappingAgent script (sees which app)
B: Network level (router/bridge)Full packet payload, timingtcpdump on mirror port
C: DNS (resolver)All resolved domainsPi-hole log or DNS pcap

Correlate by timestamp. If phone shows com.whatsapp connecting at 14:03:22, and router pcap shows traffic to 157.240.1.35:443 at 14:03:22, and DNS log shows edge-mqtt.facebook.com resolved at 14:03:21 — triangulated.

Android: Best Method Without Root

PCAPdroid (Recommended — No Root Required)

Creates a local VPN, captures all traffic with per-app attribution. Exports pcap files.

# Install: Play Store → "PCAPdroid"
# Or: https://github.com/emanuele-f/PCAPdroid/releases

# Configure:
# 1. Open PCAPdroid
# 2. Set capture mode: "PCAP File"  
# 3. Enable "Show connection details" for process mapping
# 4. Start capture
# 5. Export .pcap file
# 6. Upload to Lattice:

curl -X POST https://firestar-defense.vercel.app/api/ingest \
  -H "Content-Type: application/octet-stream" \
  -H "X-Device-ID: android-$(getprop ro.serialno)" \
  --data-binary @/sdcard/PCAPdroid/capture.pcap
Why PCAPdroid is best for Android: It captures full pcap WITH process/app attribution — no root, no ADB, no computer needed. The VPN loopback means the phone captures its own traffic including which app generated each packet.

Termux Agent (More Detail, Needs ADB or Root for Full Power)

# Without root (partial — connections only, no pcap):
curl -sL https://firestar-defense.vercel.app/agents/phone-capture-android.sh | bash

# With root (full capture):
su -c "tcpdump -i any -c 5000 -w /sdcard/capture.pcap" &
# Then upload when done

iOS: Best Methods

Method A: rvictl (Mac + USB — Recommended)

# On Mac with iPhone connected USB:
curl -sL https://firestar-defense.vercel.app/agents/phone-capture-ios.sh | bash

This is the Apple-sanctioned method. Full pcap. No jailbreak. Requires physical USB connection to a Mac.

Method B: Network-Level (No Mac, No Jailbreak)

If you can't use rvictl, capture at the router/gateway (see infrastructure section above). The phone's IP will be in the pcap.
