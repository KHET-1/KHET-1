# PLAN: Mode Differentiation & Source Attribution

## Problem Statement

The system currently has no clear separation between:
- Online vs offline analysis
- Agent-submitted vs human-uploaded vs offline-imported evidence
- Web-generated vs toolkit-generated reports

A court, a reviewer, or even the operator cannot look at a result and immediately know: how was this produced, what touched the network, and what didn't?

---

## Proposed Architecture

### 1. Source Types (every submission tagged)

| Source Type | How it arrives | Tag |
|------------|----------------|-----|
| `agent:android` | Phone agent script POSTs automatically | Auto-tagged by User-Agent + X-Source-Type header |
| `agent:ios` | iOS agent (rvictl or jailbreak) POSTs | Auto-tagged |
| `agent:desktop` | Desktop drip_trace.sh POSTs | Auto-tagged |
| `web:upload` | Human drops file on /ops/upload.html | Tagged by upload page JS |
| `offline:import` | User ran toolkit locally, then uploads report JSON | Tagged by import form (separate from raw upload) |
| `offline:local` | Toolkit ran entirely offline, never touches web | Report metadata only (never hits API) |

### 2. API Changes (`/api/ingest`)

```
POST /api/ingest
Headers:
  X-Device-ID: <device identifier>
  X-Source-Type: agent:android | agent:ios | agent:desktop | web:upload | offline:import
  X-Capture-Time: <ISO timestamp>
  X-Analysis-Mode: online | offline
  Content-Type: application/json | application/octet-stream
```

If `X-Source-Type` is not provided, infer from:
- Content-Type `application/octet-stream` + no X-Source-Type → `web:upload`
- User-Agent contains "Python-urllib" or "curl" + X-Device-ID starts with "android-" → `agent:android`
- Fallback: `unknown`

### 3. Results Display Changes (`/ops/agents/results.html`)

Each result card shows:
- **Source badge**: colored pill showing source type
- **Mode badge**: ONLINE or OFFLINE
- **Analysis status**: raw (just captured) vs analyzed (council results attached)

```
┌─────────────────────────────────────────────┐
│ cap-1778747039395-yy1a                      │
│ Device: company-phone-1                     │
│ Source: [AGENT:ANDROID]  Mode: [ONLINE]     │
│ Size: 51.2 KB | Time: 2026-05-14 08:20 UTC │
│ Status: RAW (awaiting offline analysis)     │
└─────────────────────────────────────────────┘
```

### 4. Report Metadata (toolkit output)

Every report generated by `./starfire` already declares:
```json
{
  "mode": "OFFLINE_ZERO_AI",
  "network_calls_made": 0,
  "ai_api_calls_made": 0
}
```

Add:
```json
{
  "source_type": "offline:local",
  "generation_environment": {
    "hostname": "<redacted or included>",
    "toolkit_version": "1.0.0",
    "analysis_timestamp": "...",
    "evidence_sealed_at": "...",
    "internet_available": false
  }
}
```

### 5. Offline Import Flow

New page: `/ops/import.html` (separate from upload)

Purpose: User ran `./starfire` locally and wants to publish results to the shared board.

Accepts: `starfire_report.json` + `chain_of_custody.json` + optional `merkle_manifest.json`

Validates:
- Merkle root in report matches manifest
- Chain of custody hashes can be independently verified
- Mode is declared as OFFLINE

Tags as `offline:import` in the results system.

### 6. Shared Board (`/board/`)

Shows all submissions from all sources, tagged:

```
SHARED FINDINGS BOARD
─────────────────────
[AGENT:ANDROID] company-phone-1 | 2026-05-14 | RAW capture | 51KB
[WEB:UPLOAD]    analyst-upload   | 2026-05-14 | RAW pcap    | 12MB
[OFFLINE:IMPORT] ryan-local     | 2026-05-14 | ANALYZED    | Verdict: SUSPICIOUS
[AGENT:DESKTOP]  macmini-1      | 2026-05-13 | RAW capture | 35KB
```

Filter by: source type, analysis status, device, date

### 7. User Silos (`/u/<user-id>/`)

Each user gets:
- Their own upload/import endpoint
- Their own results view (only their submissions)
- Ability to "publish to board" when ready
- Separate Merkle tree per user (their evidence chain)

Cross-user visibility only through the shared board.

### 8. Court Declaration

The formal report includes a section:

```
ANALYSIS ENVIRONMENT DECLARATION

This analysis was performed:
  Mode:           OFFLINE (no network access during analysis)
  AI Involvement: NONE (zero AI API calls)
  Source Data:    Agent-captured from [devices] + manually uploaded PCAPs
  Toolkit:        StarFire v1.0.0 (deterministic, reproducible)
  Internet:       Not available during analysis pipeline execution
  
Evidence submitted to shared platform AFTER analysis for presentation purposes only.
Analysis results are reproducible from sealed evidence + toolkit without network access.
```

## Implementation Order

1. **API: Add X-Source-Type header support + auto-inference** (30 min)
2. **Results page: Add source/mode badges** (30 min)
3. **Toolkit: Add generation_environment to report metadata** (15 min)
4. **Import page: /ops/import.html for offline result publishing** (45 min)
5. **Board page: /board/ with filtering** (1 hr)
6. **User silos: /u/<id>/ scaffold with auth placeholder** (1 hr)
7. **Formal report: Analysis Environment Declaration section** (15 min)

## Open Questions for Review

1. Should agent submissions be auto-analyzed on the server (requires tshark on serverless — currently can't), or always tagged as RAW until offline analysis is attached?
2. Should the board be publicly visible or require authentication?
3. Should user silos use simple API keys, or full OAuth (GitHub login)?
4. Should offline imports require the full Merkle manifest, or is report JSON + custody JSON sufficient?
5. How do we handle conflict when two users analyze the same pcap and reach different conclusions?

- Should the API enforce source type or is best-effort tagging acceptable?
